# EVALUATION

Two kinds of evidence are reported here:

1. **The 14-file sample corpus** (`sample_submissions/`, ground truth in
   `dataset_manifest.json`). It covers every assignment scenario, but has only
   3 positive pairs and 1 declared LLM document, so its precision/recall numbers
   carry very wide error bars.
2. **Public-dataset benchmarks** (`benchmarks/`). They run the engine's own code
   on labelled data at a larger scale: HC3 (human vs ChatGPT), pre-2019 Wikipedia,
   MRPC and PAWS (paraphrase), a 400-document injected-plagiarism corpus, 60k real
   vectors for index scaling, and an ASR word-error-rate test.

Everything between `<!-- AUTO -->` markers is regenerated by
`run_integrity_check.py --eval`; nothing in those tables is typed by hand. The prose
outside the markers cites numbers from the same run.

## Setup and reproduce

```bash
bash scripts/setup_env.sh                                   # venv + CPU torch + models
.venv/bin/python run_integrity_check.py --input_dir ./sample_submissions \
    --output_dir ./reports --skip-web --eval ./sample_submissions/dataset_manifest.json
.venv/bin/python benchmarks/fetch_data.py                   # public datasets (~16 MB)
for b in ai_detection ai_ood paraphrase retrieval index_scaling asr; do
  HF_HUB_OFFLINE=1 .venv/bin/python benchmarks/bench_$b.py; done
.venv/bin/python -m pytest tests -q                         # 34 tests
```

The corpus run uses `--skip-web` so the numbers are reproducible offline. The web
tier is tested separately (see "External signal" below).

**LLM provenance.** `06_llm_generated_summary.pdf` is genuine LLM output: its body was
generated by GLM in a single pass on 2026-11-04. The prompt is recorded in
`docs/03_llm_generated_sample.md` and in the manifest fields `generated_by` /
`generation_prompt_summary`. **Every other synthetic document was also
machine-written.** They were drafted inside an AI coding-assistant session, not
typed by a person. The manifest calls them "originals" because they are
original *with respect to each other*. They are **not** human ground truth for the AI
detector. For that reason the AI detector is judged on HC3 and Wikipedia, not on
the corpus.

How to read this table: every listed document really is machine-written (see
"LLM provenance"). So the AI_LIKELY labels are correct, and the UNSURE labels on

What these numbers show:

* **Peer engine (400 docs, 79,800 pairs).** Sentence-evidence scoring separates
  plagiarised pairs from clean pairs almost perfectly (AUC 0.99998). At the shipped
  MEDIUM threshold of 20 % it finds 75 of 80 injected pairs (39/40 verbatim, 36/40
  paraphrase) with 3 false-positive pairs. One of those 3 is a real near-duplicate
  that HC3 itself contains (two revisions of the same Wikipedia "data warehouse"
  paragraph), so it is a labelling error rather than an engine error. The other two
  are pairs of Wikipedia definitions on neighbouring topics with two consecutive
  sentences at cosine 0.66–0.78. The 12 template documents produce **zero**
  pair score (Scenario 4 at scale). A chunk-only pipeline, which was the spec design,
  reaches AUC 0.637 on the same data. That gap is why the peer score was moved to
  sentence evidence.
* **Paraphrase signal.** On MRPC, raw MiniLM cosine (AUC 0.736) is *not* better
  than token Jaccard (0.761) at the single-sentence level, because MRPC pairs share
  most of their words. On the Scenario-2 slice (true paraphrases with Jaccard < 0.35),
  cosine ≥ 0.65 catches 73/100. The assignment's 0.80 cutoff catches only 30/100.
  On PAWS (word-swaps that change meaning), cosine ≥ 0.80 flags 98 % of the
  *non*-paraphrases. Single-sentence embeddings cannot tell "A bought B" from
  "B bought A". This is why the engine requires runs of aligned sentences, and why a
  match is always shown to a reviewer rather than auto-penalised.
* **AI detector.** On HC3 the classifier is perfect (AUC 1.000) and the fused score
  at the AI_LIKELY band has precision 0.99 / recall 0.99 / human FPR 1 %. Treat
  this as an upper bound: HC3 has been public since 2023 and may be in the detector's
  training data. On pre-2019 Wikipedia (human) vs the corpus' machine-written
  documents, the classifier alone scores ≥ 0.5 on 10 of 30 human texts. The fused
  score keeps all 30 out of AI_LIKELY, but 11 of them land in UNSURE, and 3 of the
  10 machine-written documents do too. GPT-2 perplexity *inverts* on this domain
  (AUC 0.007): the machine-written business text has higher perplexity than the
  Wikipedia text.
* **Index scaling.** At 60k vectors, Flat search costs 7.7 ms per single query, or
  4.8k queries/s batched, with exact recall. HNSW (M=32, efSearch=128) costs
  0.41 ms per query at recall@10 = 0.993. Memory is 92 MB vs 108 MB. Build time is
  0.06 s vs 7.3 s.
* **ASR.** With natural-pace TTS, whisper-tiny reaches WER 0.06–0.14 at a real-time
  factor of about 0.07. whisper-base is not better on these clips (0.09–0.13) and
  is 1.7× slower. Speeding the same text up to 270 wpm raises WER to 0.44–0.54 for
  both models (see failure study 1).

**External signal (web tier) smoke test.** The corpus run uses `--skip-web`. In a
separate run with the web tier on, the full sample corpus took 133.6 s (vs 73.7 s for an offline run on the same day)
and returned no web hit above the Jaccard 0.35 floor. That is expected, because the
synthetic texts are not on the web. A probe document containing the real 2018
Wikipedia SWOT intro returned 5 web sources (economicrelated.wordpress.com, an
INFLIBNET e-book chapter, collegesidekick, and others) at Jaccard 0.36–0.66 and an
external score of 51.5 %. Web results change over time, so this is not part of
the reproducible tables.

## Failure Case Study 1: fast synthetic speech made the cross-modal copy invisible

**What happened.** The first dataset build fit the 103-word pitch paragraph into the
30-second limit by speeding espeak-ng up to 270 wpm (28.9 s clip). whisper-tiny
transcribed "Operating margins" as "Operating Mugins", "carton" as "cotton", and
"carrier swap" as "communist war". WER against the script was **0.661**. The current
engine, run on that original file from commit `990c823` together with 07, returns
**0 multimodal matches and peer 0.0 %** for both files. 08 is LOW, and 07 is MEDIUM
only because of its AI score. Scenario 1 silently failed: no error, just a clean
report for a copied video.

**Why.** Evidence needs aligned sentences at cosine ≥ 0.65 (or 0.45 with token-LCS
≥ 0.60). At WER 0.66, the best transcript-to-page cosine was 0.51 for the whole
passage, and no sentence pair survived the alignment floor.

**Fix applied and measured.** The narrator now reads the first three sentences
(78 words) at natural pace with flite. The clip is 25.1 s and WER is 0.061. The
pair now scores 100 % coverage, page 2 ↔ 00:00:00–00:00:25, with 3 aligned
sentences at cosine 0.96–1.0. `bench_asr.py` shows the speed effect does not depend
on the voice: 270 wpm gives WER 0.44–0.54 for both clips and both Whisper sizes.

**Production fix.** Accented, fast or noisy real speech will hit the same wall.
(1) Record ASR confidence (`avg_logprob`, `no_speech_prob` per segment). When it is
low, put the report into a "transcript unreliable, human listen required" state
instead of returning a clean LOW. (2) Escalate low-confidence clips to
whisper-small or a larger model (an ingestion-only cost). (3) Add a phonetic or
character-n-gram matcher for transcripts, since "Mugins"/"margins" still share most
characters. None of this is implemented. The prototype does not warn when a
transcript is garbled.

## Failure Case Study 2: the AI signal cannot be trusted on polished business prose

**What happened.** On 30 human-written Wikipedia business intros (pre-2019, so
pre-ChatGPT), the DeBERTa classifier gives p ≥ 0.5 on **10/30** and p ≥ 0.99 on
4/30. Examples: "Porter's generic strategies" 0.999, "Last mile (transportation)"
0.998, "Electronic invoicing" 0.995. The fused score keeps them out of AI_LIKELY
only by a narrow margin: "Porter's generic strategies" scores 64.8 against a band
edge of 65.0. On the corpus, the same ±1-point margin decides whether the three
machine-written template answers (12–14) are UNSURE (64.7–64.8) or AI_LIKELY. GPT-2
perplexity, the classic "explainable" detector, ranks the two groups in the
*opposite* order on this domain (AUC 0.007). Figure-dense writing has high
perplexity whoever wrote it, and the curve fitted on chatty HC3 ChatGPT answers
(perplexity ≈ 9) does not carry over.

**Why it matters.** Case-competition submissions are exactly this register:
formal, structured, number-heavy, and often written by non-native English
speakers. That is where detectors have the highest false-positive rates (Liang et
al. 2023 report 61 % on TOEFL essays). Our in-distribution HC3 result (precision
0.99) would give a false sense of safety.

**What the prototype already does.** AI is the lowest-precedence signal: on its own
it can raise a report to MEDIUM ("review lead"), never to HIGH. Every UNSURE or
AI_LIKELY report carries the ESL caveat. Model output and heuristic output are never
blended.

**How to fix.** (1) Calibrate on in-domain human writing, such as past
competition submissions from before 2022 with consent. Set the AI_LIKELY threshold
at a fixed low human-FPR operating point, as the model card does (0.5 % FPR ⇒
ai_score ≥ 0.976), instead of using a fused score whose two statistical
components fail on this domain. (2) Drop burstiness (AUC 0.29 on HC3) and gate
perplexity by domain. (3) Report AI likelihood only as a band with a
confidence statement, never as a precise percentage.

## Trade-off analysis: embedding model and vector index vs compute

* **Embedding model: all-MiniLM-L6-v2 (384-d, 22.7M params).** This is the model
  the assignment names, and it runs on any CPU. Measured throughput is 160
  sentences/s at batch 128 on 6 cores, and 29 chunks/s for 200-token chunks.
  Its weak spots are measured above: single-sentence paraphrase AUC 0.736 on MRPC,
  and blindness to word order on PAWS. The engine compensates with structure
  (runs of aligned sentences, template discount) rather than a bigger model. The
  upgrade path is e5-base-v2 or bge-base (768-d, about 3× slower; used by the
  PAN'25 plagiarism team that reported MiniLM recall problems), plus a cross-encoder
  re-ranker on the few candidate pairs. That rerank step only runs on flagged
  pairs, so its cost scales with the number of suspects, not with N².
* **Index: FAISS IndexFlatIP (exact cosine on L2-normalised vectors).** At corpus
  scale (29 chunks, ~300 sentences) any index is instant. At the 10k-submission
  scale (~30k chunks, ~300k sentences) Flat is still practical for a batch job:
  60k vectors cost 0.21 ms per query batched. ANN only pays off when the job turns
  into a stream of single queries (HNSW: 0.12–0.41 ms vs 7.7 ms per query at 60k)
  or when the index grows past a few million vectors. HNSW's 0.7–4 % recall loss at
  efSearch 32–128 means missed evidence. For an integrity tool, a missed copy costs
  more than milliseconds, so exact search is the default and HNSW the documented
  switch (see README scaling brief).
* **Compute.** The expensive part is the AI detector (DeBERTa-large, ~4 s per
  document on CPU, 1.7 GB RAM), not retrieval. ASR is cheap for short clips: RTF
  0.07 with whisper-tiny int8. A smaller detector (desklib v1.01 is the same size;
  tropa-mini has no smaller variant) or a GPU pool for the classifier is the main
  lever on cost.

## Known limitations of this evaluation

* Corpus metrics come from 14 files and 3 pairs. Use the benchmark numbers for
  any claim about accuracy.
* The 400-document benchmark injects copies of about one third of a document,
  built from human text (HC3) and human-labelled paraphrases (MRPC). It does not
  cover partial or patchwork copying below ~2 sentences, translated plagiarism, or
  adversarial obfuscation.
* The MEDIUM threshold (20 %) and the evidence-run rule were chosen with the
  retrieval benchmark in view. No separate held-out plagiarism corpus was built, so
  the 0.96 / 0.94 figures are slightly optimistic.
* Overlap is flagged symmetrically: a source and its copy get the same peer
  score (Turnitin convention). Deciding who copied whom is out of scope.
* The ASR test uses synthetic TTS speech, not human or accented speech.
